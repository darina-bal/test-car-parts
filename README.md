# Подбор автозапчастей и аналогов

Клиентское приложение на React и Redux для поиска автозапчастей через API Favorit Parts
([описание API](https://lk.favorit-parts.ru/static/wsprice.pdf)). Подбор в два этапа:

1. Вводите артикул (Enter или «Найти») — приложение показывает производителей, выпускающих деталь.
2. Выбираете производителя — приложение показывает искомую позицию и её аналоги: название и
   производитель, цену, остаток.

Стек: Vite, React 19, Redux Toolkit, React Router, Bootstrap 5 (только CSS), JavaScript без TypeScript.

## Запуск

Нужен Node.js 22.22 или новее.

```sh
npm install
npm run dev       # разработка: http://localhost:5173
npm run build     # сборка в папку dist
npm run preview   # посмотреть собранную версию: http://localhost:4173
```

## Ключ API

По умолчанию используется демо-ключ из документации API. Чтобы подставить свой, создайте файл
`.env.local` (в git он не попадает) по образцу [.env.example](.env.example):

```sh
cp .env.example .env.local      # в Windows: copy .env.example .env.local
# затем впишите в .env.local:  VITE_API_KEY=ваш-ключ
```

Ключ вшивается в клиентский код и виден в браузере: так устроено любое приложение без своего сервера.
Для публичного размещения ключ нужно прятать за серверным прокси.

С демо-ключом сервис отвечает `Request quota exceeded!` на грузовые бренды (например, HAFFEN) —
приложение показывает это сообщением «Превышен лимит запросов по грузовому ассортименту».

## Структура

```
src/
  main.jsx            точка входа: Redux Provider и BrowserRouter
  App.jsx             маршруты: / — главная, всё остальное — «Страница не найдена»
  api.js              запросы к API, разбор ответа, перевод ошибок, подготовка данных для интерфейса
  store.js            Redux-хранилище
  partsSlice.js       состояние двух этапов и два асинхронных запроса (searchBrands, loadOffers)
  pages/              HomePage (основной экран), NotFoundPage
  components/         SearchForm, BrandList, OffersTable (+ OffersTable.css), Loader, Notice
  index.css           общие стили
```

## Состояния и ошибки

Загрузка показывается лоадером, кнопки на время запроса блокируются. Обрабатываются: нет сети и
таймаут (20 с), HTTP-ошибки, ответ не в JSON, ошибки самого API (известные переведены на русский,
остальные показываются как есть), «ничего не найдено» и позиции без остатка.

## Допущения и особенности API

- Поиск запускается по Enter или кнопке, а не на каждый символ: меньше запросов и расход квоты.
- Одна строка таблицы — одна позиция. Цена — минимальная среди предложений (складов) с остатком,
  поэтому выводится как «от …»; остаток — суммарный по складам. Поле `price` верхнего уровня не
  используется (документация: «НЕ ИСПОЛЬЗОВАТЬ»), разбивка по складам не показывается.
- Первой идёт искомая позиция, дальше аналоги: сначала в наличии (по возрастанию цены), затем без остатка.
- Валюта — рубли (в документации не указана).
- Запросы идут на HTTPS-адрес сервиса; CORS у него открыт, прокси не нужен.
- Сервис сам нормализует артикул и бренд (регистр, пробелы, дефисы), на клиенте убираются только
  пробелы по краям.
- Ошибки приходят с HTTP 200 в виде `{"error": ...}`, тексты местами отличаются от документации
  (например, `Invalid access key`).
- Для ненайденной детали сервис возвращает не пустой массив, а один «пустой» элемент — он отфильтровывается.

Не входит в проект: тесты, ESLint и Prettier, пагинация и виртуализация таблицы, фильтры,
признак «невозвратная позиция» (`info=on`), кратность (`rate`), прокси для продакшена.

## Размещение

Приложение — статические файлы из `dist`. Если оно лежит не в корне домена, собирайте с префиксом:
`npm run build -- --base=/подпапка/`. Сервер должен отдавать `index.html` на неизвестные адреса,
иначе вместо страницы «Страница не найдена» пользователь увидит 404 хостинга.
